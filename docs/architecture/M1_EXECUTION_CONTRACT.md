# M1 长任务执行契约：双宿主可交付闭环

版本：v1.0 · 生效日期：2026-08-02 · 状态：**ACTIVE — G6 IN PROGRESS**

> 当前进度和已获授权以 `PROJECT_HANDOFF_STATUS.md` 为准：G1–G5 已通过，Blender 真实 G6 已通过，Vectorworks 2024 GUI approved job 待执行。本文继续作为完成标准和权限边界，不重复维护测试数字或工件 hash。
>
> 本文件是 openBIMAgent 从“工程 Alpha”推进到“受控 Beta 候选”的持续执行契约。它约束目标、实施顺序、权限边界、阶段门禁、汇报方式和停止条件。M1 内部默认连续推进，不因常规文件修改、测试失败或局部返工等待人工确认。

## 1. 长任务目标

使用同一份版本化 `CompiledUtilityIR`，完成以下可复核闭环：

```text
市政需求与工程事实
  → MunicipalRuleSet / Solver
  → CompiledUtilityIR
  → BlenderBuilder + VectorworksBuilder
  → 双宿主语义一致性检查
  → IFC/IDS 与 RuleEvidence 验收
  → Artifact Manifest + 审计记录 + 可恢复执行状态
```

M1 不以“代码已实现”为完成标准，而以一个正式市政案例能够确定性生成、校验、恢复和交付为完成标准。

## 2. 范围

### 2.1 本任务包含

1. 生产级 `VectorworksBuilder` 的确定性适配边界与模拟执行链。
2. 通用 Loop 的 `deliver` 主链接线。
3. Blender / Vectorworks 双宿主语义一致性协议和自动验收。
4. IFC/IDS 最小可交付切片及自动验证。
5. 中断、超时、拒绝、重启、幂等重试和审批恢复测试。
6. 一个正式市政示范案例及完整交付清单。
7. 对应 Schema、测试、架构文档、使用说明和验收报告。

### 2.2 本任务默认不包含

- 通用路线寻优、自动避障和水力计算。
- Web 产品化、多人远程控制面和云部署。
- 新建筑领域 Domain Pack。
- 扩大规范规则覆盖面，除非当前案例闭环所必需。
- 对 Subagent Runtime 进行与 M1 交付无关的抽象重构。

这些事项只有在不扩大架构边界、且为解除 M1 阻塞所必需时才能纳入；否则进入后续里程碑。

## 3. 执行里程碑与门禁

### G1：Vectorworks 确定性 Builder

实施内容：

- 定义 `CompiledUtilityIR → Vectorworks execution plan` 的显式映射。
- 对对象类型、图层、分类、记录字段、单位、坐标和命名进行版本化约束。
- 生成宿主可执行命令，但不让宿主重新解释自然语言。
- 实现执行前校验、稳定对象标识、幂等键、失败关闭和回滚/补偿信息。
- 先使用 fake/mock executor 完成自动化测试。

门禁：

- 同一 IR 重复编译得到 canonical-equivalent execution plan。
- 缺字段、非法版本、越权命令和未知对象类型失败关闭。
- 重试不重复创建已确认成功的对象。
- 单元测试、相关集成测试和静态检查通过。

### G2：Deliver 与 Artifact Manifest

实施内容：

- 完成 `core/loop.py::_tool_deliver()` 的确定性接线。
- 统一登记模型文件、IFC/IDS、规则报告、证据摘要、截图和执行日志。
- 工件记录包含 hash、媒体类型、生成者、来源 attempt、协议版本和状态。
- 未通过 Domain Gate、缺少必要工件或 hash 不一致时禁止标记为交付成功。

门禁：

- 离线案例能产生可 Schema 校验的 Manifest。
- Manifest 中所有本地工件存在且 hash 可复算。
- 重复 deliver 使用稳定幂等语义，不覆盖不可变历史工件。
- 失败和部分完成状态可审计。

### G3：双宿主语义一致性 E2E

实施内容：

- 建立宿主无关的语义快照协议。
- 同一 `CompiledUtilityIR` 分别驱动 Blender 与 Vectorworks 模拟执行器。
- 比较对象数量、稳定 ID、拓扑、坐标、尺寸、坡度、材质/分类映射和领域属性。
- 明确允许差异，例如宿主内部对象句柄和表现层材质细节。

门禁：

- 基准案例双宿主语义一致性自动通过。
- 人为注入坐标、尺寸、拓扑或属性偏差时能稳定失败。
- 比较报告能定位到具体对象、字段和来源 IR。

### G4：IFC/IDS 最小交付切片

实施内容：

- 从可信 IR/宿主语义快照生成或导出 IFC 最小交付物。
- 建立 IDS 要求，覆盖当前案例的分类、属性、标识和必要关系。
- 将 IFC/IDS 验证结果纳入 Domain Gate 和 Artifact Manifest。

门禁：

- 基准案例通过 IFC/IDS 自动验证。
- 删除必要属性、破坏分类或关系时验证失败。
- 验证结果可回溯到 IR 对象和规则/交付要求。

### G5：失败恢复与副作用安全

实施内容：

- 覆盖宿主拒绝、超时、部分成功、进程中断、审批暂停和 Runtime 重启。
- 验证 rehydrate 后继续执行，不静默重放旧工具副作用。
- 验证 ActorRef、attempt 谱系和 idempotency key 在交付链中的一致性。

门禁：

- 所有失败场景均有明确、持久化且可恢复的终态。
- 不出现重复建模、重复 deliver 或历史工件被覆盖。
- 恢复路径有自动测试和审计证据。

### G6：真实宿主审批门

进入本阶段前必须获得 JY 明确批准。

实施内容：

- 在副本工程中运行真实 Blender 和 Vectorworks。
- 禁止覆盖原始工程文件。
- 比较真实宿主语义快照与模拟 E2E 结果。
- 记录宿主版本、插件版本、能力声明、执行日志和产物 hash。

门禁：

- 至少一个真实市政案例在两个宿主中完成或得到可归责的外部阻塞结论。
- 模拟器没有掩盖宿主 API 差异。
- 真实执行中的所有写操作均经过既定审批和范围锁。

### G7：Beta 候选总验收

- 运行完整测试、静态检查、编译检查、Schema 校验和文档断链检查。
- 产出正式验收报告与示范案例交付清单。
- 更新 README、ARCHITECTURE、COMPONENTS 和项目状态。
- 验收通过后创建本地语义化提交，不推送远端。

## 4. 持续执行权限

### 4.1 可自主执行

- 阅读、检索和分析项目文件及公开技术资料。
- 修改 `src/`、`tests/`、`schemas/`、`domain_packs/` 和项目文档。
- 新建 M1 必需的源码、Schema、测试、fixture 和项目内工件。
- 运行测试、构建、静态检查、格式检查、编译检查和离线 E2E。
- 诊断并修复当前阶段发现的缺陷和关联回归。
- 进行不改变产品边界的内部接口调整和测试重构。
- 添加有明确必要性的项目级依赖并更新锁文件；禁止系统级或全局安装。
- 在每个 G1–G5、G7 门禁通过后创建本地 Git 提交；禁止自动推送。

### 4.2 先执行、在门禁报告中说明

- 为保持测试通过而进行的关联修复。
- 局部内部 API 重命名或抽取。
- fixture、模拟器和测试目录结构调整。
- 不改变协议语义的 Schema/文档澄清。

### 4.3 必须先审批

- 改变已确定的核心架构、协议语义或权限模型。
- 降低测试、证据、Domain Gate、幂等性、安全或审计标准。
- 扩大 M1 范围或改变完成标准。
- 启动或写入真实 Vectorworks/Blender 工程。
- 使用凭据、连接非公开外部服务或产生付费调用。
- 推送远端、创建 PR、发布、部署或对外发送内容。
- 删除、覆盖或迁移重要项目文件。
- 安装系统软件、修改系统配置或执行不可逆操作。

### 4.4 禁止默认执行

- 绕过测试、审批、Schema 或安全门禁。
- 自动确认真实宿主中的不可逆操作。
- 重放可能产生副作用的旧工具调用。
- 将密钥、token 或个人数据写入仓库、日志或工件。
- 强制推送、重写 Git 历史或擅自发布。

## 5. 汇报和中断规则

采用“仅门禁与阻塞汇报”：

- 里程碑内部持续推进，不因普通测试失败或局部设计选择暂停。
- 每个门禁报告必须包含：变更文件、关键行为、测试证据、已知限制、风险和本地提交号。
- 遇到失败时，先在现有权限内诊断并采用可逆方案修复。
- 只有以下情况暂停：需要产品取舍、需要提升权限、真实外部依赖不可用、继续执行将降低既定标准、或存在破坏性风险。
- 阻塞报告必须给出已确认事实、不能继续的原因、推荐选择和备选方案，不能只报告“失败”。

## 6. Git 与工件纪律

- 每个阶段门禁通过后形成一个边界清晰的本地提交。
- 不混入与当前门禁无关的重构。
- 不自动推送远端。
- 不提交 `.env`、凭据、运行时 token、临时缓存或真实项目原件。
- 正式结果进入稳定文档或 `outputs/`；一次性中间产物在结论固化后清理。
- 删除受版本控制的重要文件必须先审批；清理只针对可证明可再生的临时产物。

## 7. M1 完成定义

只有全部满足时，M1 才能标记完成：

1. 同一版本化 IR 可驱动 Blender 与 Vectorworks，并通过语义一致性检查。
2. 至少一个市政案例形成模型、IFC、IDS、RuleEvidence、Manifest 和审计记录。
3. Domain Gate 能阻止规则 UNKNOWN、交付缺件和语义不一致进入成功态。
4. 中断、拒绝、超时和重启后可以恢复，且不重复副作用。
5. 真实宿主验收已获批准并完成，或有明确、可复核的外部阻塞结论。
6. 完整自动化验收通过，文档与实现一致。
7. 本地提交完成，未推送远端。

## 8. 当前启动点

契约生效后从 **G1：Vectorworks 确定性 Builder** 开始。真实宿主操作保持关闭，直到 G6 获得 JY 明确批准。
