# 调研协议(RESEARCH PROTOCOL)

适用对象:所有 `docs/relays/` 下的调研提示词(Gemini / GLM 通用)。每个调研提示词开头都要求先读本文件并严格遵守。

## 1. 方法论(五段式)

1. **发现**:多关键词 web 搜索(项目名 / 领域词 + awesome 清单 / Papers with Code / GitHub topic),不放过「有任何一个相关模块」的项目。
2. **候选清单**:每个候选记录 URL、stars、最近提交、许可证、一句话定位。
3. **初筛**:按「与 openBIMAgent 的模块相关性」打分 A/B/C,C 级只留一行结论不深读。
4. **深读**:A/B 级读源码关键文件(不是只读 README),摘录落 `raw/`。
5. **模块级提取**:按 §4 模板产出——**我们要的是可拆走的模块,不是项目简介**。

## 2. 中间产物目录约定

```
relay_workspace/
  <NNN_task_slug>/          # NNN = relay 编号,如 003_3d_cad
    logs/                   # 命令输出、执行日志
    scripts/                # 调研脚本(.py 仅用标准库,或在 relay_workspace/.venv 里装)
    raw/                    # 抓取的网页/源码摘录原文
    notes.md                # 过程笔记(候选清单、筛选理由)
```

- `relay_workspace/` 整体不进 git(根 `.gitignore` 已忽略);**只有 `docs/research/` 下的正式报告入库**。
- 脚本可复用:写得干净的脚本可建议主会话提升到 `tools/` 入库。

## 3. 铁律

- 只读 `D:\devloop\workSpace\app_codex\GenerativeBIM\openBIMForge` 和 `...\GenCAD-main`,一个字节都不改。
- 不装全局依赖;不跑破坏性命令;克隆外部仓库只能克隆到 `relay_workspace/<NNN>/raw/` 内。
- 每个项目**必须标注许可证**,并评估传染性(GPL 系对开源分发的限制要显式写出)。

## 4. 报告输出契约

正式报告写入 `docs/research/NN_<slug>.md`(NN 见各提示词指定),结构:

- 开头 **TL;DR ≤200 字**。
- 每个项目一节,固定模板:

```
## <项目名>(URL · stars · 最近活跃 · License)
- 一句话定位
- 架构形态
- 可拆走模块表:模块 | 文件/包 | 接口形态 | 外部依赖 | 集成成本(低/中/高) | 许可证兼容
- 相关机制(与我们相关的部分,给文件路径+行号或 commit)
- 价值评级:A(直接可用)/ B(改造可用)/ C(仅参考)
- 建议动作:直接依赖 / fork 改造 / 抄设计重写 / 仅参考 / 忽略
```

- 事实与推断严格分开标注;外部事实附来源(URL + 文件路径 + 行号/commit)。
- 末尾两节:「横向对比表」+「对 openBIMAgent 的建议(按价值排序,注明影响哪篇架构文档哪节)」。
- **回执**:报告最后一节「入库检查单」——产出文件清单 / 未完成项 / 建议下一步。用户回「NNN 完成」后主会话照单评审。

## 5. 与主会话的对接

Gemini 写完报告即完成接力;用户只需告诉主会话「NNN 完成」。主会话读报告 → 按质量门(RELAY_WORKFLOW §质量门)审 → 通过则更新 wiki 索引并提炼进架构文档,不通过则出返工提示词。
