# 多模型接力开发工作流（Relay Workflow）

版本：v3 · 2026-08-03

状态：**REFERENCE — 方法仍有效，不再绑定 K3/Kimi 或固定模型品牌**

> 历史上由 K3/Kimi 主会话承担架构、编排和 Wiki 同步，GLM/Gemini/Grok 承担实现或调研。K3 是会话/模型身份，不是项目里程碑。Relay 001–018 已执行并在 `466afba` 中收口；一次性任务书保留于 Git 历史，不恢复到当前 Wiki。

## 1. 适用场景

仅在以下情况使用 Relay：

- 大范围但边界明确的代码实现。
- 独立、可并行、需要深入检索的调研。
- 大批量测试、迁移或格式化。
- 当前主执行者缺少某一宿主、模型或工具能力。

当前连续门禁任务优先由一个接管会话按 `PROJECT_HANDOFF_STATUS.md` 持续推进，避免为了“多模型”把强依赖链切碎。

## 2. 角色分工

| 角色 | 职责 |
|---|---|
| 主执行/架构会话 | 维护目标、契约、权限、任务分解、质量门、Git 边界和 Wiki 状态 |
| 实现接力 | 按固定文件范围实现代码、测试和局部文档，不改变架构或降低门禁 |
| 调研接力 | 给出带来源的事实、推断、风险和可执行建议，不直接修改产品结论 |
| 宿主操作人 | 在明确授权范围内执行 Blender/Vectorworks GUI 动作，返回真实工件和日志 |
| 验收者 | 独立复核 diff、测试、Schema、工件、hash、宿主证据和成熟度结论 |

模型名称和额度策略属于运行配置，不属于长期文档契约。

## 3. 标准流程

1. 主执行者先读取：
   - `docs/architecture/PROJECT_HANDOFF_STATUS.md`
   - `docs/architecture/PROJECT_MASTER_WORKFLOW.md`
   - 当前阶段执行契约
2. 将任务写成自包含提示词，明确目标、输入、文件范围、禁止事项、验收和回执。
3. 接力者只在授权范围内执行，所有事实以真实命令、文件和工件为证。
4. 接力者提交结构化回执；主执行者不得直接相信摘要，必须独立复核实际改动。
5. 通过质量门后整合入库，更新交接状态；不通过则给出具体返工项。
6. 一次性提示词和临时工作区在正式结论入库后清理，必要时由 Git 追溯。

## 4. 提示词契约

必须包含：

- 工作区绝对路径。
- 当前 HEAD、门禁和已知受保护内容。
- 需要读取的权威文档。
- 允许修改的精确文件或目录。
- 禁止事项和需审批事项。
- 正向、负向、回归和静态检查要求。
- 工件、报告和 Git 提交要求。
- 失败、中断和上下文不足时的恢复记录。
- 不伪造输出、测试数字、hash、行号或宿主事实。

## 5. 回执契约

实现类回执至少包含：

1. 实际修改文件。
2. 关键行为和协议变化。
3. 运行过的命令及真实结果。
4. 未运行项目及原因。
5. 已知风险和下一动作。
6. 本地 commit hash（若任务要求）。

调研类回执至少包含：

1. 事实与推断分离。
2. 来源路径或 URL。
3. 与当前架构的差异。
4. 推荐吸收、延后或拒绝的理由。

真实宿主回执至少包含：

1. 应用和版本。
2. 输入计划、授权根目录和输出路径。
3. operation receipts、日志和错误。
4. 模型/sidecar 的大小与 SHA-256。
5. 是否发生幂等重放及结果。

## 6. 主会话质量门

- **范围**：没有越界修改或混入接管前工作。
- **契约**：Schema、typed allowlist、权限和幂等语义未降低。
- **测试**：新增行为有正向、负向和回归证据。
- **工件**：文件存在、可打开、hash 可复算、身份绑定正确。
- **宿主**：模拟与真实结果明确区分。
- **文档**：架构、组件、交接状态和验收报告按治理规则同步。
- **Git**：提交边界清晰，不包含凭据、临时缓存、真实工程原件或 `.workbuddy/`。

## 7. Wiki 同步

接力任务收口后：

- 当前门禁、HEAD、测试、工件和下一动作更新到 `PROJECT_HANDOFF_STATUS.md`。
- 架构、路线或完成标准变化更新到 `PROJECT_MASTER_WORKFLOW.md`、`ARCHITECTURE.md`、`COMPONENTS.md`。
- 新设计裁决进入 `DECISIONS_DRAFT.md` 附录或单独 ADR。
- `docs/README.md` 只更新索引、状态标签和变更日志，不复制实现细节。
- 阶段证据进入 `outputs/` 正式验收报告。

详细规则见 `docs/architecture/DOCUMENTATION_GOVERNANCE.md`。
